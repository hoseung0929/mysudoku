# UI/UX 화면 정리 결과 (완료·실패 · 기록 · 전체 화면 검증)

작업 기준일: 2026-09-20 · 브랜치 `fix/ipad-landscape-layout` · 커밋하지 않은 작업 트리 기준
이 문서는 `docs/worklist.md`의 마지막 3단계 명세(완료·실패 화면 → 기록 화면 → 전체 화면 검증)와, 그 앞에서 함께 진행한 홈·퍼즐 선택 화면 변경까지 정리한다. 앞선 통합 검증은 [ux-integration-review.md](ux-integration-review.md).

## 1. 화면별 최종 구조

### 완료 다이얼로그 (`GameCompleteDialog` + `GameResultDialogFrame`)
다이얼로그 방식 유지. 위에서 아래로:
① 작은 축하 이미지(72, 태블릿 88) → ② "퍼즐 완료"(22 굵게) → ③ 난이도·문제 번호(14) → ④ 시간·실수(하나의 옅은 배경, 같은 너비 2열, 큰 글씨 1.3배 초과 시 세로) → ⑤ 조건부 한 줄(오늘의 도전 > 새 최고 기록, 최대 1개) → ⑥ 주요 버튼 → ⑦ 보조 버튼.
- 힌트 사용 횟수는 0보다 클 때만 작은 보조 문장으로 표시(완료 데이터로 `hintsUsed` 전달).
- 다음 퍼즐이 있으면 주요 "다음 퍼즐" / 보조 "퍼즐 목록으로". 없으면 주요 "퍼즐 목록으로" / 보조 "같은 퍼즐 다시 풀기". 같은 퍼즐을 "다음 퍼즐"로 표시하지 않는다.
- 규격: 바깥 좌우 여백 ≥ 20, 최대 너비 400, 내부 좌우 24, 높이 ≤ 안전 영역의 85%, 주요 버튼 ≥ 48, 보조 버튼 ≥ 44. 본문은 스크롤·버튼은 하단 고정, 높이 320 미만이면 전체 스크롤.
- 버튼은 연타해도 한 번만 동작(내부 플래그).

### 게임오버 다이얼로그 (`GameOverDialog`)
같은 틀(`GameResultDialogFrame`) 사용. ① "실수 한도에 도달했어요" ② "이번 게임: 실수 N회 / 한도 M회"(실제 값) ③ 안내 문장 ④ 주요 "처음부터 다시 풀기" ⑤ 보조 "퍼즐 목록으로". 빨간 배경·평가 문구·광고/결제 유도 없음. 재시작 범위는 기존 정책 그대로이며 완료 기록은 건드리지 않는다.

### 기록 화면 (`RecordsStatisticsScreen`)
1. 제목 "기록"(24 굵게) + 설정 버튼(44×44, 툴팁) — 프로필 편집은 홈에서만 접근.
2. 이번 주(월~일 7칸: 완료한 날은 채움+체크, 오늘은 테두리+"오늘", 요일 탭 시 해당 날 표시) + "활동 N일 · 완료 N판".
3. 난이도별 기록: 선택 칩(가로 스크롤) → 선택한 난이도 한 묶음(퍼즐 완료 N / 전체 + 얇은 진행 바, 최고 기록, 최고 기록 평균, 최고 기록의 평균 오답, 집계 기준 한 줄).
4. 활동 달력(기존 히트맵, 제목 옆 "최근 26주", 캡션=범례, 연속 일수 요약 행).
5. (업적 기능은 2026-10-03에 제거됨 — 아래 업적 관련 서술은 당시 기록)
6. 하단 보조 문장: 전체 완료 개수.
- 기록이 전혀 없으면 "첫 퍼즐을 완성하면 기록이 쌓여요." + [퍼즐 시작하기](홈 탭으로 이동). 로딩·조회 실패(재시도)·기록 없음을 구분. 일부 난이도만 없으면 "아직 완료한 기록이 없어요."와 "—".
- 태블릿: 최대 너비 960 가운데 정렬, 폭 ≥ 860이면 좌(이번 주 + 난이도별) / 우(달력 + 업적) 2칼럼(간격 24), 좁으면 단일 칼럼.

### 홈 (`HomeScreen`)
1. 프로필 헤더(변경 없음, 기록 화면과의 공유는 끊음) 2. 주요 시작 카드: 진행 중 게임이 있으면 "이어서 풀기"(난이도·번호·진행률/"메모 작성 중", 여러 개면 "진행 중인 게임 모두 보기 (N)" → 저장 게임 목록), 없으면 "새 게임 시작"(첫 사용자는 다른 제목·문구) 3. 오늘의 도전 카드(미시작/진행 중/완료 구분, 완료 시 보조 버튼) — 이어하기와 같은 문제면 카드를 합치고 "오늘의 도전" 칩만 표시 4. "새 게임 · 난이도 선택" 난이도 카드(빈칸 수 + 완료 현황).

### 퍼즐 선택 화면 (`LevelPickerScreen`)
완료 현황 → 대표 이어하기 1개("진행 중 N개 보기"는 진행 중 필터로 연결) → "다음 새 퍼즐 시작" → 개수가 붙은 필터(줄바꿈) → 번호 그리드. 빈 상태 4종·로딩/오류 구분·연타 방지.

## 2. 유지·이동·제거한 UI 요소

| 구분 | 요소 |
| --- | --- |
| 유지 | 완료·실패 다이얼로그 방식, 히트맵, 홈의 난이도 카드와 설정 진입, 게임 보드·숫자패드, 저장 게임 목록 화면(이제 홈에서 연결) |
| 이동 | 전체 초기화 → 게임 앱바 ⋮ 메뉴, "다른 난이도"(완료 화면) → 제거(홈 탭이 난이도 선택 위치), 연속 일수 → 달력 아래 작은 행, 전체 완료 개수 → 하단 보조 문장 |
| 제거(화면에서만) | 완료 화면의 "추천 다음 단계" 영역·알림 칩·큰 축하/최고 기록 이미지 이중 표시, 기록 화면의 대형 전체 요약 카드·주간 카드·활동 KPI 카드·모든 난이도 상세 카드 나열, 홈의 "나만의 속도" 줄과 큰 보라색 오늘 카드, 게임오버의 빨간 강조 |
| 데이터·저장 로직 | 삭제 없음. 통계 서비스 계산은 그대로(이름·설명만 실제 의미로 수정) |

연결하지 않은 것: 기록 화면의 "상세 기록 보기" — 연결할 문제별 기록 화면이 없어 만들지 않았다.

## 4. 발견하고 수정한 문제

| 문제 | 수정 |
| --- | --- |
| 홈 카드가 오늘의 도전 대신 다른 게임을 열고 일반 이어하기와 섞임 | 카드 분리·타깃 일치(앞 작업) + 이번 단계에서 주요 시작 카드/오늘의 도전 카드로 재구성 |
| 홈 재로딩마다 스피너가 깜빡이고, 늦게 끝난 요청이 최신 결과를 덮을 수 있음 | 첫 로딩 후에는 기존 화면 유지, 요청 번호로 최신 결과만 반영 |
| 저장 게임 목록 화면이 어디에도 연결돼 있지 않음 | "진행 중인 게임 모두 보기"에서 연결, 삭제 전 확인창 추가(완료 기록은 유지) |
| 완료 화면 버튼이 연타되면 이중 팝/이동 가능 | 한 번만 처리 |
| 완료 화면이 알림 설정 없는 화면·같은 난이도 목록 등으로 잘못 유도 | 제안 영역 제거 |
| 좁은 화면에서 필터 칩이 화면 밖에 숨음(가로 스크롤) | 줄바꿈으로 변경, 칩 높이 44 |
| 큰 글씨에서 난이도 카드 제목/진행 라벨, 오늘의 도전 상태 줄, 이어하기 카드 오버플로 | 줄바꿈(Wrap)·세로 배치로 전환 |
| 게임 셀에 접근성 이름이 없음 | 위치·값(또는 메모)·고정/힌트/오답·선택 상태 시맨틱 추가 |
| 통계 이름이 계산과 어긋남 | 앞선 명칭 정리 + 기록 화면에서 "최고 기록 평균" 등으로 적용 |

## 5. 미검증 항목과 실기기 확인 사항

- **(갱신) 위 3절의 크기·글씨 검증은 테스트 뷰 크기 변경이다.** 2026-09-21에 iPhone 17 시뮬레이터로 주요 화면을 실제로 확인했다(7절). 실기기 확인은 여전히 하지 못했다.
- 스크린 리더: 의미 구조(라벨·선택 상태·노드 수) 검사까지만 했다. 실제 VoiceOver/TalkBack 낭독은 미검증.
- 동작 감소 설정: 이번에 퍼즐 카드의 반복 발광 애니메이션을 제거했지만, 전체 앱의 다른 애니메이션이 시스템 "동작 줄이기" 설정을 따르는지는 확인하지 않았다.
- 기록 화면 요일 칸은 320px 폭에서 가로 약 40px(높이 76)로 44px 미만이다. 보조 조작이라 유지했으며 실기기에서 조작성 확인 필요.
- 업적 화면(`AchievementCollectionScreen`)은 연결만 했다. 자체 데이터 로딩·오류 문구는 있으나, 실제 DB 데이터와의 일치는 이번에 검증하지 못했다(서비스가 주입 불가).
- 일본 플레이버(`arb/japan`)는 문구를 같은 키로 함께 갱신했고 `flutter gen-l10n`으로 생성했다(플레이버 설정 변경 없음). 일본 플레이버로의 실제 빌드는 하지 않았다.
- Apple Pencil 필기 인식은 실기기 없이 검증하지 않았다.
- 완료 후 홈·기록 복귀 갱신은 `GameRecordNotifier` 경로를 그대로 사용하며, 실제 DB로 완료까지 이어지는 통합 테스트는 없다.
- 캡처한 스크린샷: 파일로 저장하지 않음(7절은 시뮬레이터 화면을 직접 보고 기록).

| 결함 | 원인 | 수정 |

### 이번에도 확인하지 못한 것
- **작은 휴대폰(320pt)**: 사용 가능한 가장 작은 시뮬레이터가 iPhone 16e/17급(약 390pt)이라 320pt는 위젯 테스트로만 확인.
- **아이패드 가로**: 시뮬레이터 회전 표시가 이 환경에서 신뢰할 수 없어(기존 기록 참고) 실화면 확인하지 않음.
- **실기기**·VoiceOver 낭독·Apple Pencil·오늘의 도전 자정 통과 시나리오.
- 실수 제한으로 게임오버되는 화면(게임오버 다이얼로그), 오늘의 도전 완료 후 홈 상태, 기록 화면의 활동 달력 하단.

## 9. 홈 후속 수정 (2026-09-21)

이미지 보강(8절)은 유지하고 확인된 네 가지 문제만 수정했다. 캡처는 `docs/screenshots/home-polish-after/`에 새로 저장했고 기존 before/after 캡처는 보존했다(사용자 데이터 없는 새 설치 상태, iPhone 17 시뮬레이터).

### 1. 다크 모드 상태바 대비
- 원인: 홈의 `AnnotatedRegion`이 `statusBarIconBrightness: dark`로 고정되어 다크 모드에서 시계·배터리가 검게 표시됨. iOS용 `statusBarBrightness`도 지정되지 않았음.
- 수정: `lib/theme/system_ui_style.dart`의 `systemOverlayStyleFor(brightness)`가 테마 밝기에서 Android(`statusBarIconBrightness`, 아이콘 색)와 iOS(`statusBarBrightness`, 화면 밝기)를 **서로 반대 방향의 값**으로 계산. 홈이 `Theme.of(context).brightness`로 호출. 전역 `SystemChrome` 설정은 추가하지 않음.
- 실화면(iOS 시뮬레이터): 라이트 홈, 다크 홈, 홈→게임→홈, 홈→기록(다크)에서 시계·통신·배터리가 배경에서 읽힘. 실행 중 시스템 테마 전환과 설정의 앱 내 테마 변경도 즉시 반영(`08-theme-switched-to-light-in-app.png`).
- **Android 미검증**: 실행하지 못했고, 값 계산(테스트)까지만 확인.

### 2. 시작 버튼 문구
- "새 게임 시작" → **"난이도 선택"**(첫 사용자·진행 중 없는 기존 사용자 공통). 동작(난이도 영역으로 스크롤)은 그대로이며 게임을 시작하지 않음.
- 키 분리: `homeChooseLevelButton` 신설. 이 버튼에만 쓰이던 `homeStartNewButton`과 앞 작업에서 만든 `homeNoInProgressTitle`·`homeStartNewBody`·`homeFirstStartBody`는 사용처가 없어져 제거. 다른 "시작하기" 문구는 건드리지 않음. 5개 언어(global 5 + japan 3 ARB) 반영, `flutter gen-l10n`으로 생성, 플레이버 설정 변경 없음.
- 스크롤: 고정 헤더 뒤로 가려지지 않도록 스크롤 목표에서 헤더 높이를 뺌(태블릿 레이아웃은 본문이 헤더 뒤로 스크롤됨). 목표 위치까지 못 가는 경우에도 끝까지 스크롤되어 난이도 제목과 카드가 보임(`06-after-choose-level-tap.png`).

### 3. 홈 프로필 헤더
- 한 줄 구조: **[아바타 38] 이름 [설정]**. 인사말·소개 문구는 홈 헤더에서 표시하지 않음(`ProfileGlassHeader.showSubtitle` 기본 false; 인사말 코드와 소개 데이터·편집 기능은 유지).
- **실제 기본 높이: 상태바 아래 64pt**(위아래 여백 8 + 조작 영역 48). 이전에는 약 104pt + 상태바. 아바타 그림 38, 설정 버튼 48×48(툴팁 "설정"), 프로필 조작 영역 최소 높이 48, 이름 17pt/700.
- **큰 글씨·긴 이름**: 고정 높이가 아니라 최소 높이. 이름은 최대 두 줄(말줄임, 접근성에는 전체 이름), `FittedBox` 없음. 이전 작업에서 넣었던 헤더 글씨 1.3배 상한은 제거해 시스템 배율을 그대로 따르고, 본문 위치는 **추정 상수 대신 렌더링된 헤더 높이를 측정**해 예약(`_headerHeight`, 상태바 inset 중복 적용 없음). 그래서 헤더가 커져도 첫 카드가 가려지지 않음(테스트: 배율 1.0/1.6/2.3).
- 헤더와 첫 카드 간격 18 → 14. 프로필 편집(아바타·이름 탭)과 설정 진입은 실화면에서 동작 확인. `ProfileGlassHeader`는 홈에서만 쓰임.

### 4. 큰 글씨에서 시작 카드 간소화

- 문구: 첫 사용자 "첫 퍼즐을 시작해보세요", 기존 사용자 "새 퍼즐을 시작해보세요"(이전 "진행 중인 게임이 없어요" 제거), 공통 설명 "난이도를 선택하세요. 진행 상황은 자동 저장됩니다." 데이터 판정 로직은 변경 없음.

## 11. 인터랙션 효과 정리 (2026-09-21)

- 게임 효과 우선순위: 퍼즐 완료 > 행·열·박스 완성 > 일반 정답. 일반 정답은 입력 칸만 180ms 강조(기존 행·열 파동 대체). 줄 완성은 합집합 한 번, 550ms. 마지막 입력은 줄 효과·안내 없이 결과창만.
- 오답: 해당 칸만 ±3px, 약 200ms. 칸·효과별 토큰으로 재입력 시 이전 종료 콜백이 새 효과를 지우지 않음. 백그라운드 전환 시 임시 효과 정리.
- 선택 칸은 강조 중에도 테두리로 유지.
- 눌림: `PressScale`(0.98, 누름 90ms/복원 130ms) — 문제 타일, 홈 난이도 카드. 카드 안 버튼은 Material 기본 반응.
- 결과창 캐릭터: 280ms 페이드+0.94→1.0, 인스턴스당 1회. 오늘의 도전: 같은 날짜 미완료→완료 전환 시 체크만 200ms 페이드.
- 동작 줄이기: 흔들림·확대·펭귄 뒤뚱거림 생략, 상태는 즉시 표시.
- 실기기 미확인: 오늘의 도전 완료 전환(자동 테스트만), 실제 진동/체감 부드러움. 영상: `docs/screenshots/interaction-effects/flow.mp4`.
