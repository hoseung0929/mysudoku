  - **12개 항목 UI/UX 튜닝 완료** (2026-09-06, 사용자 상세 스펙 기반) — 보드/기존 로직은 그대로 두고 우측 패널만 조정: 카드 세로 패딩 20%↓(20→16), 카드 간 gap↓(16→12), 라벨 색 `onSurfaceVariant`→`onSurface`로 진하게, 진행률 카드에 얇은 `LinearProgressIndicator` 추가(`SudokuInfoCard`에 옵션 `progressValue` 파라미터), 통계 패널~키패드 사이 `Spacer()` 하나를 `Spacer(flex:1)+콘텐츠+Spacer(flex:6)+콘텐츠+Spacer(flex:1)`로 나눠 중간 gap 25%↓(위아래엔 살짝 여백 생겨 균형 유지), 숫자패드 버튼 폭에 밀도 계수 0.92 적용(8%↓, 랜드스케이프 전용 클래스라 폰 영향 없음), 잔여개수 뱃지 25%↑·숫자패드↔액션버튼 gap +10px(둘 다 `_buildNumberButton`/그 호출부에 새 옵션 파라미터 `largeBadge`/gap 상수 추가, 기본값 false라 폰 호출부는 그대로), 메모 버튼 활성 시 아이콘도 포인트 컬러로(`emphasizeActiveIcon` 옵션, 역시 기본 false), 타이머 포맷 1시간 미만 MM:SS로 변경(`_formatCalmTime`/presenter의 `calmFormattedTime` 둘 다), 오답 0개일 땐 경고색 대신 중립 톤. **보류**: 숫자 버튼 색이 연하다는 항목은 확인해보니 실제로 칸을 선택하면 이미 완전 불투명 진한색(#1F1F1F)이 나옴 — 지금까지 스크린샷이 전부 "칸 미선택" 상태(의도된 디자인)였을 뿐이라 변경하지 않음.
  - **가운데 여백 추가 개선** (2026-09-07) — 위 튜닝 후에도 "여전히 통계 카드~키패드 사이가 넓다"는 피드백에 따라 두 가지 더 적용: (1) `_kLandscapeMidSpacerFlex`를 6→3으로 더 낮춰 중간 gap을 60%까지 축소, (2) 통계 카드+진행률바+숫자패드+액션버튼 전체를 테두리 하나(배경은 안 채움, `context.colors.border` 1px + radius 22)로 감싸서 "제각각 떠 있는" 느낌 대신 하나의 컨트롤 패널처럼 보이게 함. 이 과정에서 위젯 테스트가 실제 오버플로우 버그 2건을 잡아냄: 패널 안쪽 padding(16px×2)만큼 숫자패드가 쓸 수 있는 폭/높이가 줄었는데 `numberButtonWidth`/`estimatedBlockHeight` 계산에 반영이 안 돼 있었음 → `_TabletLandscapeGameLayoutMetrics.fromConstraints()`에 `panelPadding` 파라미터를 추가해 `usableKeypadWidth`/`keypadContentHeight`로 보정. 그 과정에서 한 겹 더: `numberButtonWidth`의 하한 64가 좁아진 폭에서는 오히려 넘치게 만들 수 있어서, 하한을 `math.min(64, rawWidth)`로 바꿔 "정확히 들어맞는 값" 위로는 절대 강제로 안 올리게 함(사용 가능한 폭이 아주 좁을 때만 64보다 작아짐, 평소엔 그대로 64). 위젯 테스트 2개 다시 통과, 시각 확인 완료.

  - **미해결/다음 단계**: 실기기(아이패드+애플펜슬)로 셀 위에 실제로 써보는 검증이 아직 남음 — 셀이 너무 좁아 불편하면 플랜B(가로 모드 우측 패널에 고정 크기 필기란을 두는 방식, 내부 로직은 거의 동일해서 전환 비용 작음)로 전환.
  - **V2(그리드 위 몰입형 필기, 네이티브 브릿지) 관련 정정**: 애초 검토했던 "PencilKit(`PKCanvasView`)+네이티브 브릿지"는 **PencilKit 자체엔 필기 인식 기능이 없어서** 틀린 접근이었음 — 실제로 필요한 건 Apple 자체 앱(메모/캘린더 그리드 입력)이 쓰는 `UIIndirectScribbleInteraction`(화면의 여러 영역을 "엘리먼트"로 등록하면 시스템이 각 영역별로 인식 UI+콜백을 제공)이다. 이 조합을 다루는 기존 Flutter 플러그인이 없어 처음부터 Swift 델리게이트 구현 + `MethodChannel`/`UiKitView`로 81셀 좌표를 동기화해야 하는 더 큰 네이티브 작업 — V1 실기기 검증 후, 별도의 작은 네이티브 스파이크(더미 3~4칸)로 먼저 리스크를 낮추고 나서 본 구현 착수하기로 함.

  - **알림 권한 요청 + 자동 재동기화 하드코딩 완료** — 설정 UI 토글을 되돌리면서 권한 요청 호출부(`requestNotificationPermissions()`)도 같이 사라졌던 걸 발견 → `main.dart`의 `_bootstrapNotificationState()`에서 `initialize()` 직후 `requestPermissions()`를 직접 호출하도록 복구. iOS/Android 모두 사용자가 이미 응답한 뒤엔 재호출해도 시스템 프롬프트가 다시 뜨지 않으므로 별도 "최초 1회" 플래그 없이 매 실행마다 호출.
  - **알림 발송 조건도 "오늘의 챌린지 클리어"에서 "오늘 아무 퍼즐이나 1판 클리어"로 변경** — 챌린지 탭의 "시작하기" 버튼이 실제로는 `MyPaceService`(이어하기/진행순서 로직)로 열려서 오늘의 챌린지 타깃과 다른 퍼즐을 여는 경우가 많다는 걸 확인, 알림 조건을 실제 동작에 맞게 단순화. `syncReminders()`도 이제 `isTodayChallenge` 여부와 무관하게 매 클리어마다 재동기화됨 (`notification_service.dart`, `game_completion_coordinator.dart`).
  - 남은 이슈: 챌린지 탭 "시작하기" 버튼이 여전히 화면에 표시된 오늘의 챌린지 타깃과 다른 퍼즐을 열어주는 라벨-동작 불일치는 미해결 (별도 작업 필요). 이번 알림 관련 변경이 출시되는 다음 업데이트의 App Store 심사 노트에 반영할 것.

## 고도화 백로그 (우선순위순, 2026-09-13 경쟁사 조사 후 재배치)

경쟁 스도쿠 앱(sudoku.com, Good Sudoku, Enjoy Sudoku, Logic Wiz, Andoku 3 등) 조사 결과를 반영해 2026-08-17 순서에서 재배치함. 자세한 조사 근거는 이 세션 대화 참고.

1. **힌트 풀이 설명** — 정답만 채우지 않고 실제 기법명(예: naked pair, X-Wing, pointing triple)으로 왜 이 숫자인지 설명. Good Sudoku/Enjoy Sudoku/Logic Wiz 등에서 확인된 핵심 차별화 포인트라 1순위로 상향.
2. **자동 메모 채우기** — 버튼으로 각 칸 후보 숫자 일괄 채우기 (상급자용, on/off 가능). Good Sudoku의 대표 기능("auto-annotation")으로 확인됨. 1번(기법 설명)과 세트로 묶으면 시너지(설명한 기법이 실제로 쓰는 후보 숫자를 자동 표시).
3. **iOS 홈 화면 위젯** — 오늘 챌린지 상태·스트릭만 보여주는 WidgetKit 위젯. 서버 불필요. 위젯만으로 완결되는 경쟁 앱까지 있을 정도로 활발한 영역이라 우선순위 유지.
4. **Game Center 연동** — 자체 서버 없이 업적/랭킹 제공 가능. 여러 경쟁 앱이 채택 중이고 서버 비용이 0이라 기존보다 우선순위 상향 검토.
5. **Apple Watch 앱** (신규, 2026-09-13 조사로 발견된 갭) — Watch 전용 스도쿠 앱들이 존재함을 확인. 다만 실사용자 중 Watch 보유 비율 대비 투자 효과가 불확실해 낮은 우선순위로만 등록.
6. **macOS Catalyst 빌드** — Flutter 특성상 상대적으로 적은 작업으로 데스크톱 빌드 가능. 순위 그대로 유지(낮음).
